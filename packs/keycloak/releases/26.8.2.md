# Keycloak 26.8.2

A patch release of 26.8, published on 2026-11-05. The image is
`quay.io/keycloak/keycloak:26.8.2`, pinned by the digest of its index in the record
`26.8.2.json`. Quay builds a tag again when its base image changes, so the digest is the
artifact and the tag is the version.

- Security fixes: 33 issues, among them a stored XSS on the login page, account takeover
  through organization identity-first login, several unauthenticated denial-of-service
  paths in the SAML endpoints, an Admin API audience check, and session takeover through
  an injected `id_token_hint`.
- Quarkus 3.40.1.1.
- The migration installs a new client registration policy provider that earlier 26.8
  nodes do not know. The upgrading guide says that a rolling upgrade is not supported for
  this release: stop every node and start them on 26.8.2 together. The chart of this pack
  does that for every release (the strategy `Recreate`).
- New client scope `kc-admin-api`. Read the upgrading guide before the upgrade when a
  client of your own calls the Admin API.

Keycloak migrates its database when a new release starts, and it cannot roll the database
back. The record says `schema_change: true`: when the check after the upgrade fails, the
control plane does not go back to 26.8.1. The way back is the database backup from before
the upgrade.

Sources: https://github.com/keycloak/keycloak/releases/tag/26.8.2 and
https://www.keycloak.org/docs/latest/upgrading/index.html
